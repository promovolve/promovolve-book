# 見張らずに数える

広告の商売は、読者について3つのことを数えなければなりません。広告が本当に見られたか。1人の読者がそれを何回見たか。そしてキャンペーンが何人の別々の読者に届いたか。従来のアドテクは3つとも同じやり方で答えます——すべての読者に ID を振り、その ID のすることを記録するのです。Promovolve には読者 ID がないので、問いごとに別の答えが必要でした。その答えはどれも同じ形をしています。**記憶は読者のブラウザが持ち、サーバーが持つのは集計だけ。**

## 何をインプレッションと数えるか

広告を配信することと、見せることは同じではありません。ファーストビューの下にある広告や、一瞬で流れ去った広告は、届きはしても見られてはいません——広告主がその分を払うべきではないのです。

Promovolve は業界のディスプレイ広告の標準(MRC のビューアブルインプレッション基準)に従います。インプレッションが数えられるのは、次のときです。

- 広告のピクセルの**50%以上**が画面内にあること——970×250以上の大型フォーマットでは、標準が認めるとおり30%。
- **表示中のタブ**であること。
- それが**連続して1秒**続くこと。

連続であって、累積ではありません。広告がしきい値を下回るか、タブが裏に回れば、時計は最初からやり直しです。0.5秒の一瞥が2回あっても、1回の視認にはなりません。唯一の近道はクリックです——広告を開いた読者は明らかにそれを見ているので、インプレッションはその場で、クリックそのものより先に数えられます。

1秒が過ぎると、広告は、選択の時点でサーバーが発行した署名付き URL を通じて報告します。署名はキャンペーンと価格を縛っているので、報告を再送することも、別のキャンペーンに付け替えることも、水増しすることもできません。この報告こそがインプレッションです。広告主に課金するのも、[トンプソン・サンプリング](./serving.md)の窓が数えるのも、これです。配信されたが見られなかった広告は、何も教えず、課金もされません。

## フリークエンシーキャップ:数えるのはブラウザ

広告主はキャンペーンに上限を付けられます。1時間、1日、または1週間あたり最大 *N* インプレッション。同じ読者に同じ広告を40回目に見せるのは、広告主のお金と読者の忍耐の両方の無駄遣いです。

よくある実装は、読者 ID をキーにしたサーバー側のカウンターです。Promovolve はこれを逆さにします。

1. 勝った広告はどれも、そのキャンペーンの上限——回数と期間——と一緒に届きます。
2. インプレッションがビューアブルになったとき、広告タグはブラウザ自身のストレージに、パブリッシャーのサイトの下で、記録を1件書きます。
3. 次のリクエストの前に、タグは自分の記録を数え、上限に達したキャンペーンの名前を挙げます。サーバーはそのリストを固い除外として扱います——すでにページに出ているキャンペーンを扱うのと同じやり方で。

サーバーは、この読者が何を何回見たかを決して知りません——知るのは「今回は、このキャンペーンたち以外で」だけです。ドッグイヤーされた広告は両方向で対象外です。広告をしおりした読者は上限に関係なくそれを取り戻せますし、その再会は上限の回数に数えられません。

1つ、手直しが必要だった機微があります。上限に達したキャンペーンは勝てないので、ブラウザはその上限の新しい写しを受け取れません——上限を*外した*広告主は、古い期間が過ぎ去るまで、上限に達したブラウザに気づいてもらえないことになります。そこでタグは、抑えている各キャンペーンについて、上限がまだ有効かどうかも尋ね、サーバーが答えます。沈黙が上限を解くことは決してありません。答えがなければ、除外を続けます。

限界は、クッキーを使わないあらゆるキャップと同じ限界であり、広告主の画面にもそう書いてあります。上限は**ブラウザごと、サイトごと**です——人ごとではなく、パブリッシャーをまたぐこともありません。スマートフォンとノートパソコンは2人の読者です。サイトデータを消せば回数はリセットされます。あるパブリッシャーで上限に達した読者は、次のパブリッシャーではゼロから始まります。ブラウザのストレージは、読者がいまいるサイトのものだからです。サイトをまたぐキャップには、このプラットフォームが使わずに済ませるために存在している、まさにそのクロスサイトの識別子が必要になります。だからこれは先送りではなく、やらないと決めたことです。

## リーチ:ID なしで数えるユニーク読者

*リーチ*とは、キャンペーンを見た別々の読者の数です。これは識別なしには得られない唯一の数字に見えます。2つのインプレッションが別の人のものだと知るには、当然、それが誰かを知らなければならないはずだ、と。

その必要はありません。各ブラウザが1つの質問に答えてくれれば足ります。*このキャンペーンを、ここで最後に見たのはいつ?*

その日キャンペーンの最初のビューアブルインプレッションが起きたとき、タグはその答え——日の番号、または「一度もない」——を送り、今日を新しい答えとして保存します。報告はキャンペーンごとに1日最大1回で、中身は前回の日だけです。サーバーは集計を持ちます。このキャンペーン、このサイト、今日について——最後に見たのが1日前のブラウザがいくつ、2日前がいくつ、一度もないがいくつ。

この集計から、どんな日付範囲のユニークブラウザ数も足し算で出てきます。あるブラウザの範囲内での*最初の*訪問とは、ちょうど、前回見た日が範囲の始まりより前にある訪問のことです——どのブラウザにもそれは1つあり、1つしかありません。

\\[ \text{reach}(a \ldots b) = \sum_{d=a}^{b} \text{reports on day } d \text{ whose previous sighting was before day } a \\]

(範囲 a〜b のリーチ = 各日 d の報告のうち、前回見た日が a より前のものの合計。)

1日目、2日目、5日目にキャンペーンを見るブラウザを考えます。その報告は*一度もない*、*1日前*、*3日前*です。1〜5日目のリーチを尋ねると、条件を満たすのは最初の報告だけなので、1回数えられます。4〜5日目を尋ねると、5日目の報告は「最後に見たのは2日目」——範囲より前——と言っているので、やはり1回数えられます。どの範囲も2回は数えず、どの報告もそれが誰かを語りません。

これは Chrome のアップデーターが、インストールを識別せずにアクティブな数を数えるのに使っている方法です。Promovolve はその防御も借りています。各報告には、ブラウザが1回使ったら捨てる乱数が付いているので、同じ値が2回届けば、それはコピーされたブラウザストレージ——複製されたボットのプロファイル——を意味し、数えられません。集計は91日までの範囲で正確です。

正直な端の部分は、ここでもレポート自身に書かれています。リーチはサイトごとです。2つのパブリッシャーにいる読者は2つのブラウザなので、サイトをまたぐ合計には「最大」と表示されます。そしてストレージのないブラウザは何も送りません——記憶がなければ新しい読者と戻ってきた読者を見分けようがなく、レポートは推測するより少なく数えるほうを選びます。

リーチが手に入ると、広告主はインプレッションだけでは見えない2つの数字を読めます。**フリークエンシー**(読者1人あたりのインプレッション数)と**新規読者1人あたりのコスト**です。後者が上がったとき、レポートは理由を言います——価格が上がったのか、読者1人あたりの繰り返しが増えたのか、新しい人が尽きかけているオーディエンスなのか。
